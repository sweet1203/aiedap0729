심화 (기본 실습을 마친 뒤)

🔑 gh auth login 하나로 GitHub 연동하기

커서·클로드 코드·안티그래비티 어떤 AI 도구를 쓰든, 준비 과정은 똑같습니다. (Windows 기준)

💡 이 심화의 핵심 문장
"gh auth login 한 번이면, 어떤 AI 도구든 '이거 GitHub에 올려줘!' 프롬프트가 통한다."
이 페이지는 Windows 기준입니다. 기본 실습(코스웨어 만들기)을 마치신 분을 위한 추가 내용이에요.

0 왜 이걸 배우나요?

AI에게 코딩을 시키면(바이브코딩) 결과물이 내 컴퓨터에만 남습니다. 이걸 GitHub에 올려야 —

  • ① 코드가 안전하게 보관되고
  • ② Vercel 등으로 웹에 배포할 수 있고
  • ③ 학생·동료와 공유할 수 있습니다.

예전엔 git add → git commit → git push 명령어를 외워야 했지만, 지금은 AI에게 "이 프로젝트 GitHub에 올려줘" 라고 말만 하면 됩니다. 단, AI가 내 GitHub 계정에 들어갈 열쇠가 필요한데, 그 열쇠를 만들어 주는 것이 바로 gh auth login 입니다.

🗝️ 비유 — GitHub은 내 코드 창고, AI 도구는 심부름꾼. gh auth login은 심부름꾼에게 창고 출입증을 딱 한 번 만들어 주는 것. 출입증은 컴퓨터에 저장되어, 이후 어떤 AI 심부름꾼이든 자동으로 씁니다.

1 공통 준비 — 딱 3단계 (Windows)

어떤 AI 도구를 쓰시든 이 3단계는 동일합니다. 오늘 심화의 80%가 여기입니다.

1-1. GitHub 계정 만들기 (이미 있으면 건너뛰기)

  1. github.com 접속 → 오른쪽 위 Sign up
  2. 이메일 · 비밀번호 · 사용자 이름(영문) 입력
  3. 이메일로 온 인증 코드까지 입력하면 완료
✏️ 사용자 이름은 나중에 웹 주소에도 쓰일 수 있으니(예: username.github.io), 기억하기 쉬운 영문 이름으로. 학교 메일보다 개인 계정을 추천합니다.

1-2. Git + GitHub CLI(gh) 설치

① PowerShell(파워셸) 열기

  1. 키보드 ⊞ Windows 키를 누릅니다
  2. powershell 이라고 입력
  3. 목록에 나온 Windows PowerShell을 클릭 (검은 창이 열립니다)

② 아래 두 줄을 한 줄씩 붙여넣고 Enter (첫 줄 끝나면 둘째 줄):

winget install Git.Git
winget install GitHub.cli
⚠️ 설치 중 "이 앱이 기기를 변경하도록 허용하시겠어요?"가 뜨면 예. 설치 조건(약관) 동의를 물으면 Y 입력 후 Enter.

③ 파워셸을 완전히 껐다가 다시 켜고, 설치가 됐는지 확인:

git --version gh --version
✅ git version 2.x.x / gh version 2.x.x 처럼 버전 번호가 나오면 성공입니다.
🆘 winget이 "인식할 수 없다"고 나오면 Windows가 오래된 버전입니다. Microsoft Store에서 "앱 설치 관리자(App Installer)"를 업데이트하거나, git-scm.com·cli.github.com에서 설치 파일을 받아 설치하세요.

1-3. ⭐ gh auth login — 오늘의 주인공

파워셸에 입력:

gh auth login

질문이 순서대로 나옵니다. 방향키 ↑ ↓ 로 고르고 Enter 로 선택하세요:

화면에 나오는 질문이렇게 선택
What account do you want to log into?GitHub.com
What is your preferred protocol…?HTTPS
Authenticate Git with your GitHub credentials?Yes (Y)
How would you like to authenticate?Login with a web browser
  1. 화면에 8자리 코드(예: ABCD-1234)가 뜹니다 → 이 코드를 기억하거나 복사
  2. Enter 를 누르면 브라우저가 자동으로 열립니다 (안 열리면 화면에 뜬 주소를 직접 복사해 열기)
  3. 브라우저에서 GitHub 로그인 → 아까 그 8자리 코드 입력 → Authorize(승인) 클릭
  4. 파워셸로 돌아오면 ✓ Logged in as 내계정명 이 떠 있습니다 🎉

확인:

gh auth status
✅ 여기까지면 준비 끝! 인증 정보는 컴퓨터에 안전하게 저장돼, 아래 어떤 AI 도구를 쓰셔도 자동으로 사용됩니다. 다시 로그인할 필요 없어요.

2 내가 쓰는 AI 도구별 사용법

위 공통 준비가 끝났다면, 내가 쓰는 도구의 토글만 열어 보세요. 어느 도구든 5분이면 됩니다.

🟠 Claude Code (가장 간단!)

추가 설정: 없음. gh가 로그인돼 있으면 자동으로 씁니다.

  1. 프로젝트 폴더에서 파워셸을 열고 claude 실행
  2. 이렇게 입력:
이 프로젝트를 GitHub에 새 저장소로 만들어서 올려줘. 저장소 이름은 my-first-app 으로 해줘.
  • 클로드가 git init → 커밋 → gh repo create → push 까지 알아서 합니다.
  • 중간에 실행 허가를 물으면 Yes.
  • 이후 수정할 때마다: "지금까지 변경한 내용 커밋하고 push해줘"
💬 커밋 메시지도 클로드가 변경 내용을 보고 자동으로 써 줍니다.
🔵 Cursor (커서) — 버튼 방식 + 프롬프트 방식

방법 A — 버튼으로 (초보 추천)

  1. 왼쪽 사이드바에서 소스 제어(Git) 아이콘 클릭
  2. Initialize Repository 클릭 → 커밋 메시지 입력(예: first commit) → ✔ Commit
  3. Publish Branch / Publish to GitHub 버튼 클릭
  4. 처음이면 브라우저가 열리며 권한 허용 → 저장소 이름·공개(Public)/비공개(Private) 선택
  5. 끝! 이후엔 커밋 → Sync 버튼만 누르면 올라갑니다.

방법 B — 프롬프트로 (gh auth login 완료 시) — 에이전트 채팅(Ctrl+I)에 입력:

지금 프로젝트를 GitHub에 새 저장소 만들어서 push해줘
⚠️ 연결 버튼이 무한 로딩되면: 커서를 완전히 끄고 → 파워셸에서 git config --global --unset credential.helper 실행 → 커서 재시작 → 다시 연결.
🟢 Google Antigravity (안티그래비티) — 함정 1개!

원리는 같지만, 안티그래비티는 자체 격리된 터미널을 써서 시스템에 저장된 인증을 못 읽는 경우가 있습니다.

해결: 안티그래비티 "안의" 터미널에서 로그인

  1. 안티그래비티 상단 메뉴 Terminal → New Terminal
  2. 여기서 gh auth login 실행 (밖에서 이미 했어도, push가 안 되면 여기서 한 번 더!)
  3. 에이전트 패널에 입력:
이 프로젝트를 GitHub에 push해줘. 저장소가 없으면 새로 만들어줘.
🧩 심화(선택) — MCP Store에서 "GitHub"을 연결하면 저장소 조회·이슈 관리까지 프롬프트로 가능. 단 토큰 발급이 필요해 초보 단계에선 생략해도 됩니다. push만 목적이면 gh auth login으로 충분.
🟣 ChatGPT (Codex) — 구조가 조금 다릅니다

① 웹/앱 클라우드 방식 (계정 연결)

  1. ChatGPT 좌측 Codex → Settings (안 보이면 Plus 이상 유료 플랜 확인)
  2. Connect GitHub → 권한 부여
  3. Codex가 접근할 저장소 범위 선택
  4. 작업을 시키면 클라우드에서 코드를 고치고 PR(Pull Request)을 만들어 줍니다.
📌 "바로 push"가 아니라 "수정본을 올려 주면 내가 검토 후 Merge(승인)" 흐름. 검토 단계가 있어 오히려 안전합니다.

② 로컬 CLI 방식 — Git이 설정된 폴더에서 실행하면 자동 인식. gh 로그인이 돼 있으면:

지금 변경 내용 커밋하고 push해줘

실행 위치(저장소 폴더 안)가 중요합니다!

3 실습 미션 (함께 해보기)

4 자주 묻는 질문

Q. gh auth login은 도구마다 따로 해야 하나요?

아니요! 컴퓨터당 한 번입니다. 인증 정보가 저장돼 모든 도구가 공유합니다. 단, 안티그래비티만 예외적으로 내부 터미널에서 한 번 더 필요할 수 있어요.

Q. 학교 컴퓨터에서 안 될 때는?
  • 학교 보안 프로그램·네트워크가 github.com 인증을 막는 경우가 있습니다.
  • ① 브라우저 인증 창이 안 열리면 관리자에게 github.com 허용 요청
  • ② 급할 땐 휴대폰 핫스팟(테더링)으로 임시 우회
  • ③ 그래도 안 되면 개인 노트북으로 실습
Q. push가 갑자기 안 돼요 (Permission denied / 403)

90%는 인증 문제입니다. gh auth status로 상태 확인 → 로그아웃 상태면 gh auth login 다시 실행.

Q. Public(공개)과 Private(비공개), 뭘 고르죠?

수업 자료·학생 공유용은 Public, 성적·개인정보가 조금이라도 들어갈 수 있으면 반드시 Private! 그리고 AI가 올리기 전에 API 키·비밀번호가 코드에 없는지 꼭 확인하세요.

Q. AI가 마음대로 push해버리면?

대부분 실행 전 허가를 묻습니다(Yes/No). 중요한 프로젝트는 자동 승인을 끄고, "push 전에 나한테 먼저 확인받아"를 프롬프트에 덧붙이는 습관을 추천합니다.
